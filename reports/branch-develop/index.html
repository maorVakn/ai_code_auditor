🚨 Usage of Weak Hashing Algorithm (MD5) for Security Purposes

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The MD5 hashing algorithm is being used, likely for security-sensitive operations. MD5 is cryptographically broken and should not be used where collision resistance or strong security guarantees are required.

Risk: MD5 is vulnerable to collision attacks, meaning different inputs can produce the same hash output. If used for password storage, digital signatures, or integrity checks, an attacker could forge data or bypass authentication, compromising data integrity and security. This can lead to unauthorized access or data manipulation.

Fix: Replace MD5 with a cryptographically strong hashing algorithm. For password hashing, use a dedicated key derivation function like `bcrypt`, `scrypt`, or `Argon2`. For data integrity or general-purpose hashing, use SHA-256 or SHA-3 (e.g., `hashlib.sha256`). If MD5 is used for non-security purposes, explicitly set `usedforsecurity=False` in the `hashlib.new` call to suppress the warning.

Fix security finding B324 in `test_samples/vulnerable_app.py:32`. Issue: Weak MD5 hashing algorithm is used for security, risking collision attacks and data compromise.

A `run:` step in `action.yml` at line 52 uses variable interpolation `${{...}}` with `github` context data directly, which is a shell injection risk. The `github` context can contain untrusted user input, allowing an attacker to inject arbitrary commands into the runner.

Risk: This vulnerability can lead to severe consequences, including full compromise of the GitHub Actions runner. An attacker could steal repository secrets, modify code, delete resources, or pivot to other systems, resulting in a complete breach of the CI/CD pipeline and potentially the codebase.

Fix: Prevent shell injection by using an intermediate environment variable.
