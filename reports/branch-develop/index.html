🚨 Critical Command Injection via `subprocess.Popen` with `shell=True`

test_samples/vulnerable_app.py:27
bandit code_vulnerability B602
HIGH

The `subprocess.Popen` function is called with `shell=True`, which allows the execution of arbitrary commands if user-controlled input is passed to the command string.

Risk: Setting `shell=True` in `subprocess.Popen` is highly dangerous, as it directly exposes the application to command injection vulnerabilities. If an attacker can inject malicious input into the command string, they can execute arbitrary system commands with the privileges of the running application, leading to complete system compromise, data exfiltration, or denial of service.

Fix: Avoid setting `shell=True` in `subprocess.Popen` calls. Instead, pass the command and its arguments as a list of strings. If shell features are absolutely necessary, ensure that all user-supplied input is rigorously sanitized and quoted using `shlex.quote()` to prevent command injection, though this approach is still riskier than avoiding `shell=True`.

Mitigate command injection risk (B602) in test_samples/vulnerable_app.py:27 by removing `shell=True` from `subprocess.Popen`.

🚨 GitHub Actions: Shell Injection Vulnerability via Untrusted `github` Context

action.yml:52
semgrep code_vulnerability yaml.github-actions.security.run-shell-injection.run-shell-injection
HIGH

A `run:` step in a GitHub Actions workflow directly interpolates data from the `github` context into a shell command. `github` context data, especially fields derived from user input (e.g., pull request titles, commit messages), must be considered untrusted. Direct interpolation can lead to shell injection, allowing an attacker to execute arbitrary commands on the runner.

Risk: This flaw can lead to severe consequences, including arbitrary code execution on the GitHub Actions runner. An attacker could exfiltrate repository secrets (like `GITHUB_TOKEN`), tamper with the build artifacts, or gain unauthorized access to other systems accessible by the runner, leading to a full compromise of the CI/CD pipeline and potentially the codebase.

Fix: Instead of directly interpolating `github` context variables into the `run:` command, pass them securely via environment variables. For example:```yaml - env: MY_VAR: ${{ github.event.comment.body }} run: | echo "$MY_VAR" ```Always double-quote the environment variable when used in the shell script to prevent word splitting and glob expansion.

High: GitHub Actions shell injection via untrusted `github` context in `action.yml` at line 52. Refactor `run:` step to use environment variables for `github` context data and ensure proper quoting. Refer to CWE-78 for more details.

⚠️ GitHub Actions: Use of Mutable Action Tag Poses Supply Chain Risk

.github/workflows/security-scan.yml:22
semgrep code_vulnerability yaml.github-actions.security.github-actions-mutable-action-tag.github-actions-mutable-action-tag
MEDIUM

A GitHub Actions workflow step references an action using a mutable tag or branch (e.g., `v1`, `main`). This practice is vulnerable to supply chain attacks, as the action's owner can silently update the content pointed to by the tag/branch without your knowledge, potentially injecting malicious code into your workflow. Examples include the trivy-action and kics-github-action compromises.

Risk: This vulnerability enables supply chain attacks, where an attacker could inject malicious code into your CI/CD pipeline if they compromise the upstream action's repository or if the action owner maliciously updates the mutable reference. This can lead to code compromise, secret exfiltration, or other system breaches.

Fix: Pin the GitHub Action reference to a full 40-character commit SHA instead of a mutable tag or branch. For example, change `uses: actions/checkout@v2` to `uses: actions/checkout@<full_SHA>`, e.g., `actions/checkout@8ade135a41bc03ea155e62e844d188df1ea18608`. This ensures deterministic and auditable execution.

Medium: GitHub Actions mutable tag found in `.github/workflows/security-scan.yml` at line 22. Update `uses:` to use a full commit SHA to prevent supply chain attacks. Refer to CWE-1357 for more details.
