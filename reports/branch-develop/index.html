bandit code_vulnerability B602
HIGH

A `subprocess.Popen` call uses `shell=True`, which is highly dangerous when combined with untrusted input, as it directly executes commands via the system shell.

Risk: Using `shell=True` with untrusted input is a critical command injection vulnerability. An attacker can inject arbitrary shell commands, leading to remote code execution, privilege escalation, data exfiltration, or complete system compromise.

Fix: Avoid using `shell=True` with `subprocess.Popen` if user-controlled input is involved. Instead, pass commands as a list of arguments (e.g., `['command', 'arg1', 'arg2']`). Mitigate critical command injection (B602) in test_samples/vulnerable_app.py:27. Issue: `subprocess.Popen` used with `shell=True`, posing a severe risk.

🚨 Use of Weak Hashing Algorithm (MD5)

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The MD5 hashing algorithm is used, which is cryptographically weak and unsuitable for security-sensitive applications like password storage or digital signatures.

Risk: MD5 is vulnerable to collision attacks, meaning different inputs can produce the same hash output. This weakness makes it unsuitable for verifying data integrity, creating digital signatures, or securely storing passwords. An attacker could forge data or potentially crack hashed passwords.

Fix: Replace MD5 with a cryptographically stronger hashing algorithm, such as SHA-256, SHA-3, or Argon2 (especially for password hashing). If MD5 is used for non-security purposes (e.g., checksums for data integrity where collisions are not a security concern), explicitly set `usedforsecurity=False` in the `hashlib` function call to clarify intent.

Upgrade hashing algorithm (B324) in test_samples/vulnerable_app.py:32. Issue: Weak MD5 hash detected; consider stronger alternatives like SHA-256.
