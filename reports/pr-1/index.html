🚨 Command Injection via Subprocess with `shell=True`

test_samples/vulnerable_app.py:27
bandit code_vulnerability B602
HIGH

A `subprocess.Popen` call uses `shell=True`, which is highly dangerous if any part of the command string is derived from untrusted user input, allowing for arbitrary command execution.

Risk: Using `shell=True` allows the underlying shell to interpret the command string. If an attacker can inject malicious characters into this string, they can execute arbitrary system commands on the server, leading to full system compromise (Remote Code Execution).

Fix: Avoid using `shell=True` whenever possible. Instead, pass commands and their arguments as a list of strings to `subprocess.Popen`. If `shell=True` is strictly required, ensure all user-controlled input is rigorously validated and escaped using `shlex.quote()` to prevent command injection.

Fix security finding B602 in test_samples/vulnerable_app.py:27. Issue: `subprocess.Popen` with `shell=True` creates command injection risk.

🚨 Use of Weak Hashing Algorithm (MD5) for Security Purposes

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The MD5 hashing algorithm is used for a security-sensitive operation, such as password storage or data integrity checks, but MD5 is cryptographically broken and considered insecure.

Risk: MD5 is highly susceptible to collision attacks, making it unsuitable for security applications. An attacker could forge data with the same hash or potentially reverse-engineer hashes, compromising data integrity, user authentication, or other security guarantees.

Fix: Replace MD5 with a strong, modern cryptographic hashing algorithm. For password hashing, use algorithms designed for this purpose, like bcrypt, scrypt, or Argon2. For data integrity, use SHA-256, SHA-512, or SHA3 variants.

Fix security finding B324 in test_samples/vulnerable_app.py:32. Issue: Weak MD5 hashing algorithm used for security-sensitive operation.
