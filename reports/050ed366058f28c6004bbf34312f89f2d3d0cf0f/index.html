🚨 Command Injection Risk with subprocess.Popen and shell=True

test_samples/vulnerable_app.py:27
bandit code_vulnerability B602
HIGH

The use of `subprocess.Popen` with `shell=True` can expose the application to command injection vulnerabilities if user-controlled input is passed to the command string without proper sanitization.

Risk: If an attacker can control parts of the command string, they can execute arbitrary shell commands on the system, potentially leading to remote code execution, data exfiltration, or system compromise.

Fix: Avoid using `shell=True` with `subprocess.Popen`. Instead, pass the command and its arguments as a list to `subprocess.Popen` (e.g., `['ls', '-l']`). If `shell=True` is absolutely necessary, ensure all user-provided input is thoroughly sanitized and escaped.

Address command injection vulnerability by avoiding `shell=True` in `subprocess.Popen` (B602) in test_samples/vulnerable_app.py:27.

🚨 Usage of Weak Hashing Algorithm (MD5)

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The application uses the MD5 hashing algorithm, which is cryptographically weak and has known collision vulnerabilities, making it unsuitable for security-sensitive operations like password storage or digital signatures.

Risk: Attackers could exploit MD5's weaknesses to create hash collisions, potentially forging digital signatures, compromising data integrity, or enabling password cracking, leading to unauthorized access or data manipulation.

Fix: Replace MD5 with a cryptographically strong hashing algorithm such as SHA-256 or SHA-3 for all security-sensitive operations. If MD5 is used for non-security purposes (e.g., data integrity checks where collisions are acceptable), explicitly set `usedforsecurity=False`.

Upgrade to a stronger hashing algorithm like SHA-256/SHA-3 instead of MD5 (B324) in test_samples/vulnerable_app.py:32.
