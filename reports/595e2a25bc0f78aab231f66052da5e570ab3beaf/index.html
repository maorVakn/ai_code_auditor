🚨 Arbitrary Command Execution via Subprocess with shell=True

test_samples/vulnerable_app.py:27
bandit code_vulnerability B602
HIGH

A subprocess call using `shell=True` has been identified. This is a common security risk as it allows the execution of arbitrary shell commands if any part of the command string is derived from untrusted input, potentially leading to remote code execution.

Risk: Critical. If an attacker can control any part of the command string passed to `subprocess.Popen` with `shell=True`, they can execute arbitrary operating system commands on the server, leading to full system compromise, data exfiltration, or denial of service.

🚨 Insecure Hashing Algorithm (MD5) Used for Security Purposes

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The application uses the MD5 hashing algorithm, which is cryptographically weak and unsuitable for security-sensitive operations such as password storage, digital signatures, or integrity checks. MD5 is vulnerable to collision attacks, meaning different inputs can produce the same hash output.

Risk: High. Using MD5 for security-critical functions can allow attackers to forge digital signatures, bypass integrity checks, or crack hashed passwords more easily, compromising data authenticity, integrity, and confidentiality.

Fix: Replace MD5 with a cryptographically strong hashing algorithm, such as SHA-256 or SHA-3, for security-related purposes. For password storage, use dedicated password hashing functions like bcrypt, scrypt, or Argon2, which are designed to be slow and resistant to brute-force attacks.

Fix B324 in test_samples/vulnerable_app.py:32. Issue: MD5 hash used for security. Replace with a stronger algorithm like SHA-256 or a password hashing function.

ℹ️ Process Started with Partial Executable Path (PATH Hijacking Risk)

scanner/bandit_scan.py:27
bandit code_vulnerability B607
LOW

A process is being started using an executable path that is not fully qualified (e.g., 'command' instead of '/usr/bin/command'). This allows the operating system to search for the executable in directories defined in the system's PATH environment variable.

Risk: Medium. If an attacker can manipulate the PATH environment variable or place a malicious executable in a directory that is searched before the legitimate one, they could execute arbitrary code. This is particularly risky in environments where untrusted users can influence the execution context.

Fix security finding B607 in scanner/bandit_scan.py:27: Process Started with Partial Executable Path. Use absolute paths to prevent PATH hijacking.
