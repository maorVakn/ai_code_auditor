🚨 Command Injection Risk with subprocess.Popen and shell=True

test_samples/vulnerable_app.py:27
bandit code_vulnerability B602
HIGH

The application uses `subprocess.Popen` with `shell=True`, which can introduce a command injection vulnerability if user-controlled input is passed to the command string. This allows arbitrary command execution.

Risk: Executing commands with `shell=True` makes the application highly susceptible to command injection. An attacker could embed malicious commands within user input, leading to remote code execution (RCE) on the server.

🚨 Use of Weak Cryptographic Hash (MD5)

bandit code_vulnerability B324
HIGH

The code uses MD5, a cryptographically weak hashing algorithm, for security-sensitive operations. MD5 is known to be vulnerable to collision attacks, making it unsuitable for protecting data integrity or verifying authenticity.

bandit code_vulnerability B607

ℹ️ Subprocess Call with Untrusted Input

scanner/bandit_scan.py:27
bandit code_vulnerability B603
LOW

A `subprocess` call is made without `shell=True`, but the arguments may still contain unsanitized, untrusted input. While `shell=False` is generally safer, improper argument handling can still lead to command injection if arguments are not properly separated or escaped.

Risk: Although `shell=True` is not used, if user-controlled input is directly included within the command arguments without proper sanitization (e.g., if a single string is passed as the command rather than a list of arguments, or if an argument itself contains shell metacharacters), it can still lead to command injection and arbitrary code execution.

Fix: When calling `subprocess` functions, always pass the command and its arguments as a list of strings (e.g., `['command', 'arg1', 'arg2']`). Never construct the command string by concatenating user input directly. If user input must be included, ensure it is properly sanitized and escaped for the target command, or use functions like `shlex.quote()` if shell-like behavior is absolutely required (though `shell=False` is preferred).

Fix security finding B603 in `scanner/bandit_scan.py:27`. Issue: Subprocess call with potential for untrusted input. Ensure command arguments are a list of strings and sanitized.
