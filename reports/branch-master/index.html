🚨 Use of Weak Hashing Algorithm (MD5)

test_samples/vulnerable_app.py:32
bandit code_vulnerability B324
HIGH

The `hashlib` module is used with the MD5 algorithm, which is cryptographically weak and unsuitable for security-sensitive applications like password storage or digital signatures.

Risk: MD5 is susceptible to collision attacks, making it possible for an attacker to find two different inputs that produce the same hash. This weakness can be exploited to forge data, bypass authentication, or compromise data integrity if used in security contexts.

Fix: Replace MD5 with a cryptographically strong hashing algorithm such as SHA-256 or SHA-3 (e.g., `hashlib.sha256()`). For password hashing, use dedicated password hashing functions like `bcrypt` or `argon2` that incorporate salts and work factors.

Fix B324: Replace weak MD5 hash at `test_samples/vulnerable_app.py:32` with a stronger algorithm like SHA-256.

Untrusted user input within `github` context data could allow an attacker to execute arbitrary code, leading to secret exfiltration or repository compromise.

Risk: A shell injection vulnerability in a GitHub Actions workflow can allow an attacker to execute arbitrary commands on the runner. Fix: Mitigate shell injection by avoiding direct interpolation of `github` context data in `run:` steps.
